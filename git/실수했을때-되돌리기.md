# Git 실수했을 때 되돌리기 (force push 누르기 전에)

> 자경단원이 가장 자주 막히는 자리. **상황별로 다른 명령**을 씁니다. 무작정 `git push --force`는 떼껄룩의 적입니다.

## 상황

- 방금 commit 메시지를 잘못 썼다
- 잘못된 파일을 add했다
- 이미 push한 commit을 되돌리고 싶다
- 협업 중인 브랜치를 망칠까 무섭다

## 그루밍

### A. **아직 push 안 한** 경우 — 자유롭게

```bash
# 마지막 commit 메시지만 고치고 싶다
git commit --amend -m "새 메시지"

# 마지막 commit에 파일 추가하고 싶다 (이미 add는 한 상태)
git commit --amend --no-edit

# 마지막 commit 자체를 취소 (변경은 작업 디렉토리에 남김)
git reset --soft HEAD~1

# 잘못 add한 파일 빼기
git restore --staged 파일명

# 작업 디렉토리 변경 자체를 버리기 (위험!)
git restore 파일명
```

### B. **이미 push했고 본인 혼자 쓰는 브랜치**

```bash
# 1) 새로운 "되돌리기 commit" 만들기 (안전, 권장)
git revert HEAD
git push

# 2) 정말 흔적 없이 지우고 싶다 (위험, 협업 중이면 절대 금지)
git reset --hard HEAD~1
git push --force-with-lease   # --force 보다 안전함
```

> `--force` 대신 `--force-with-lease`를 쓰세요. 다른 사람이 그 사이 push했다면 거부됨.

### C. **이미 push했고 협업 중인 브랜치 (main, develop 등)**

→ 무조건 `git revert`. force는 금지.

```bash
# 특정 commit 하나만 되돌리고 싶다
git revert <commit-sha>
git push

# 여러 개를 한 번에
git revert <oldest-sha>..HEAD
git push
```

### D. **commit 자체는 좋은데 잘못된 브랜치에 했다**

```bash
# 마지막 commit을 다른 브랜치로 옮기기
git log -1                       # SHA 확인
git reset --hard HEAD~1          # 현재 브랜치에서는 제거
git checkout 다른브랜치
git cherry-pick <SHA>
```

### E. **그냥 다 못 본 척하고 싶다**

```bash
git stash         # 작업 보관
git stash pop     # 다시 꺼내기
git stash drop    # 영원히 버리기
```

## 한 줄 요약

| 상황 | 명령 |
|------|------|
| Push 전 | `git reset` / `git commit --amend` |
| 본인 브랜치 push 후 | `git revert` 권장, 정 필요하면 `--force-with-lease` |
| 공용 브랜치 push 후 | **무조건** `git revert` |
